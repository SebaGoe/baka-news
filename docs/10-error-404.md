# 10 · Errors & the 404 Ghost

## 404 page — `Views/pages/404.php`
Full retro treatment: Bakabake front and center, a giant blackletter **404**, "the ghost ate
this page", a home button, and a blinking `booo`. Served with a real `404` status.

## How 404s happen
- **Unmatched route** → `Router::notFound()` renders the ghost page.
- **Missing content** → controllers return the ghost page with a themed title when an
  article id or category slug doesn't exist (e.g. "404 — Article Escaped",
  "404 — Category Vanished"). Keep these little jokes when you add routes.

## Error handling to add (session B)
1. **500 page** — wrap `Router::dispatch()` in try/catch (or `set_exception_handler` in
   `bootstrap.php`) that logs to `storage/` and renders a `pages/500.php` ("the ghost
   spilled coffee on the server"), status 500. Never leak stack traces in production.
2. **Env switch** — read `BAKA_DEBUG` env: on → show the error; off (default) → ghost page.
3. **JSON errors** — endpoints that return JSON already use `json_out(['ok'=>false...], code)`;
   keep that shape for API-style failures.
4. **Form re-entry** — on validation failure, flash old input via `$_SESSION['_old']` and
   `old()` (already wired for the ads form; extend to guestbook/webring if desired).

Copy voice for errors: friendly, specific, never blaming the user. "The ghost ate this
page" > "Not Found". Say what happened and offer the way home.
